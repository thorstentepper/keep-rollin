# 0007. Ship an offline price snapshot as a fallback

**Status:** Accepted — 2026-08-09
**Decision:** Bundle a small parquet snapshot of prices inside the package and
serve it, clearly flagged, when Yahoo Finance is unavailable.

## Context

Fetching live data ([0001](0001-replace-static-csv-data-with-live-market-data.md))
made the project dependent on an endpoint that rate-limits and occasionally
fails outright. A hosted dashboard that greets a visitor with a stack trace
because a third party is throttling is worse than one showing slightly stale
figures — particularly when the visitor is looking at it as a portfolio piece.

## Considered options

- **Ship a parquet snapshot in the package** — chosen. Small (under 40 KB),
  versioned with the code, and available in any environment the package
  installs into, including a container.
- **Fail with a clear error** — rejected. Honest, but leaves the most common
  first impression of the project as a broken page.
- **Cache responses to disk at runtime** — rejected. A cold environment has no
  cache precisely when it needs one, and hosted dashboards start cold.

## Consequences

- The dashboard always renders. The offline case is stated in a banner naming
  the snapshot's date range, so stale data is never mistaken for live data.
- The snapshot is generated by `scripts/refresh_fallback.py`, which validates
  before writing and refuses to overwrite a good snapshot with a short or
  empty fetch — a bad refresh cannot destroy the safety net.
- The snapshot covers a fixed set of symbols. Requests it cannot serve raise
  rather than silently substituting different assets.
- It goes stale unless someone reruns the script, and nothing enforces that.
